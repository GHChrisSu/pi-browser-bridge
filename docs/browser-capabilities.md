# Browser capability matrix

Pi Bridge covers common HTTP/HTTPS website workflows. It is a Chrome extension plus a per-agent-directory shared broker and per-session MCP adapters, not a general remote-control API for every browser surface.

## Available

| Task | How it works |
|---|---|
| Connect Chrome profiles | Each profile creates a random local ID automatically. Multiple Pi MCP sessions can share the broker; `list_profiles` reports all connected profiles, and browser tools route by `profile_id`. A custom display label is optional. |
| Inspect pages | Read visible body text, page title and URL; inspect form metadata without reading values; list visible links, buttons, and form controls. `get_css_styles` reports computed styles and readable matching CSS rules. `read_console` instruments fixed console methods on first use and returns a bounded buffer. |
| Navigate and organize | Open HTTP/HTTPS URLs, create background tabs and Pi Bridge tab groups, read up to five URLs in temporary tabs, move tabs, run explicit tab actions, and save/restore/tile Chrome window layouts. Layout matching stores origin/path only, without query strings or fragments. |
| Debug network activity | `monitor_network` observes request URL/method/type/status/timing metadata after the optional `webRequest` permission is enabled. It strips query values, collects no headers or bodies, and keeps a bounded in-memory buffer per tab. |
| Control network rules | `network_rules` can block, redirect, or modify headers through Chrome declarative rules. The optional permission is off by default. Each Pi call that changes rules requires confirmation; rules are limited to 50 per profile, can target one tab, expire within 24 hours, and clear when Chrome restarts. |
| Visual and page audits | `screenshot_diff` stores named profile-local baselines and returns changed-pixel percentage plus a red diff image. `element_screenshot` and `full_page_screenshot` capture only an already-visible tab. `audit` runs bounded read-only DOM, SEO, accessibility, security-indicator, resource, and timing checks; it does not send link probes or inspect response headers. |
| Window and table tools | `tile_windows`, `move_tab`, `window_layout`, `get_frames`, and `extract_table` provide bounded window, frame, and structured-table operations. |
| Clipboard | `clipboard` reads or writes plain text only after optional clipboard permissions are enabled and Pi confirms each operation. A read sends clipboard text into the model context; writes replace the current clipboard. |
| Advanced site access | Optional `userScripts` unlocks confirmed JavaScript execution in the page's MAIN world; optional `cookies` unlocks confirmed site-storage reads/writes and authenticated HTTP requests. These capabilities are off by default; authenticated requests refuse redirects. |
| Session and consent tools | `session_fixture` saves/restores same-origin cookies and storage in local extension storage after confirmation. `cookie_audit` clears cookies, reloads the current page, and reports metadata; it can log the user out. `http_auth` keeps confirmed Basic/Digest credentials in memory for one origin. |
| Page archive and replay | `save_page` captures an MHTML archive to a new confirmed local file. `session_record` stores a bounded safe command log under the Pi agent state directory; replay is confirmed and excludes scripts, typed values, cookies, storage, uploads, and network bodies. |
| Performance capture | `perf_trace` returns an in-memory trace summary; `frames` samples requestAnimationFrame timing. `screencast` captures a short confirmed sequence of visible-tab JPEG frames. `lighthouse` and `heap_snapshot` run in a fresh unauthenticated headless Chrome profile, not the user's signed-in tab. |
| Interact with page DOM | Click a CSS-selected element, fill ordinary supported form controls, type in ordinary inputs/textareas/contenteditable elements, press common keys, scroll, and wait for text or a selector. Every operation can target a background tab with `tab_id`. |
| Accessibility and real clicks | `get_accessibility_tree` returns Chrome's full paginated accessibility tree; `get_visible_dom` filters it to interactive nodes with snapshot-scoped IDs. `click_dom_node` revalidates a node and dispatches a real pointer event. `get_by_role`, `fill_by_role`, and `click_by_role` provide Playwright-style role/name locators backed by Chrome's accessibility tree and fixed debugger input commands; Pi Bridge does not bundle Playwright or expose arbitrary page evaluation. Form values are omitted from inspection. |
| Inspect page assets | `list_page_assets` inventories visible images, media, and download links with selectors; `download_media` can save selected HTTP(S), `blob:`, or `data:` assets. In-page assets use Chrome's Downloads API and obey the same `max_bytes` limit (50 MiB by default, 100 MiB maximum). |
| Download a file | `download_media` starts a selected page asset/control download and waits for Chrome; `download_url` fetches an explicitly requested HTTP/HTTPS URL. Both return the local path, MIME type, size, and Chrome danger state. Downloads default to a 50 MiB limit, capped at 100 MiB. Clients may overlap an explicitly requested direct download with unrelated tab setup, reads, or role actions. |
| Upload a local file | `upload_file` sets one local file up to 50 MiB on a selected `input[type=file]`. Pi requires action-time confirmation displaying the canonical path, size, profile, tab, and target website. After confirmation and completion of role/debugger actions on that tab, upload setup may overlap with an independent requested `download_url`. Keep page-control and blob downloads serialized within one profile; the website receives the file contents directly from Chrome. |
| Capture a page | Capture the currently visible viewport of the active tab as JPEG. |

## Limits

- `webRequest`, `webRequestAuthProvider`, `declarativeNetRequestWithHostAccess`, `cookies`, `userScripts`, `pageCapture`, `clipboardRead`, `clipboardWrite`, and `offscreen` are optional permissions and remain disabled until the user enables them in the extension popup.
- Network observation returns redacted metadata only; it does not collect request/response bodies, headers, or cookie values. Its in-memory buffer is lost when Chrome restarts the extension service worker.
- Network rules can affect requests across a Chrome profile when `tab_id` is omitted. In Pi, each non-list rule change requires action-time confirmation; the rules expire, and `clear` removes Pi Bridge-managed rules only.
- User-supplied page scripts require the optional `userScripts` permission and Chrome's “Allow user scripts” toggle. They execute in the page's MAIN world after Pi confirmation.
- HTTP Basic/Digest credentials require optional `webRequestAuthProvider` and `webRequest` permissions. Pi confirms changes; credentials remain in memory only and are scoped to an origin.
- Clipboard access is sensitive. Pi confirms each read/write operation; non-Pi MCP clients should configure their own confirmation policy. Reading clipboard text can expose private content to the model.
- Session fixtures can contain cookies and website storage; they persist in Chrome extension storage until deleted. Session recordings persist as mode-0600 files under the Pi agent directory and retain safe selectors/URL paths, not tool results or typed values.
- Screenshot baselines and window layouts are stored locally in Chrome extension storage. Layouts retain only URL origin/path identifiers and window bounds, not query strings or page contents.
- MHTML archives can contain private page content. The save tool requires an action-time confirmation, writes only a new file under an existing directory, and refuses sensitive/key paths.
- `cookie_audit` clears the selected page's cookies and can sign the user out. It requires confirmation and optional `cookies` and `webRequest` permissions.
- `screencast` frames may contain private page content and require per-call Pi confirmation. Performance traces are summarized in memory and do not return raw page content.
- CSS/DOM audits and screenshots can still reveal private information visible on the page. Review before sending those results to a model service.
- It cannot script browser-internal pages (`chrome://…`), extension pages, or the Chrome Web Store.
- Website cookies and local/session storage are unavailable by default. After the user enables optional `cookies` permission, `get_storage` and `set_storage` can read/write those values; Pi confirms each call because returned data can contain login secrets.
- The `downloads` permission lets Pi Bridge wait for requested downloads and return their local path. Direct HTTP/HTTPS downloads use Chrome's download API, which may send that Chrome profile's cookies for the target host. Downloads are never opened or executed automatically.
- The `debugger` permission attaches only for fixed accessibility-tree reads, node-validated pointer clicks, ordinary accessible textbox fills, pointer hover, and confirmed `upload_file` operations. It exposes no arbitrary DevTools command; page-script execution is a separate opt-in `userScripts` feature.
- Pi asks for action-time confirmation before uploads; uploads are blocked when Pi has no confirmation UI. Other MCP clients need their own upload approval policy.
- File uploads transmit the selected file to the target website. Chrome or a site-specific flow may still refuse access or submission. Pi Bridge blocks common key/credential paths and filenames.
- Page-reading and ordinary form tools inspect the top document and omit form values; cross-origin iframe controls and closed shadow roots are not traversed. `get_frames` reports frame metadata only. The separately confirmed `execute_js` tool can target a specific frame after userScripts is enabled.
- CSS-based page clicks, text entry, and keyboard tools use DOM-synthetic events. The accessibility-node click and hover use Chrome's debugger API. Sites can still reject actions that require additional user gesture context.
- Background tabs support DOM operations but not visible screenshots. Pi Bridge refuses a background screenshot instead of switching focus.
- Password, hidden, file, and token-like fields are refused by ordinary fill tools. Optional `execute_js` runs arbitrary user-supplied code in the page after explicit permission and confirmation, so it can access page data; treat every page as untrusted.
- A Chrome profile identity is a random extension-local ID, not the Chrome menu's display name. Chrome's public extension API does not expose that display name. Pi Bridge generates a short default label; changing it in the popup is optional.

When more than one profile is connected, omit `profile_id` only if the broker reports one connected profile. With multiple profiles, Pi Bridge fails ambiguous calls instead of choosing a browser silently. Read operations can run concurrently; page mutations are serialized per profile, and downloads are serialized by Chrome profile.
